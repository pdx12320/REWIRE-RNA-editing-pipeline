# Cycle 4 — Integrate RNA evidence with the 293T catalogue

## Design

### Question

How should the treatment-specific RNA table and the external 293T catalogue be combined while preserving an audit trail?

### Matching rule

The comparison used exact allele identity:

```text
CHROM : POS : REF : ALT
```

Coordinate-only matching was not used because different alternate alleles can occur at the same genomic position.

The workflow was designed to retain:

1. the original treatment-specific records with a catalogue-overlap flag;
2. the exact catalogue-overlapping exclusions;
3. the final retained screening set.

## Build

### Strict integration route

The current strict script expects REDItools2 tables, VEP annotation, candidate-depth tables for all six samples and the catalogue VCF:

```bash
python3 pipeline/scripts/rna/filter_c_to_u_and_compare.py \
  --manifest pipeline/config/samples.tsv \
  --reditools-dir "$PROJECT/reditools/tables" \
  --vep "$PROJECT/vep/CU5.17_EGFP_GC.vep.tsv" \
  --depth-dir "$PROJECT/candidate_depth" \
  --output-dir "$PROJECT/final" \
  --variant-catalogue-vcf "$CATALOGUE_VCF" \
  --min-treated-reps 3 \
  --max-control-called-reps 0 \
  --min-depth-all-reps 20
```

### Compatibility problem

The completed RNA result had been generated by an older helper implementation. At final integration:

```text
candidate_depth/ was unavailable
the site matrix lacked all_replicates_depth_pass
a completed 3,349-row treatment-specific table already existed
```

The strict script stopped instead of assuming that the missing depth field had passed.

### Compatibility solution

A dedicated exact-allele filter was added:

```text
pipeline/scripts/catalogue/filter_existing_treatment_specific_by_293T.py
```

Frozen command:

```bash
PROJECT=/data/ydx/igem/CU5.17_EGFP_GC_paper
INPUT="$PROJECT/final/CU5.17_EGFP_GC.treatment_specific.tsv.gz"
CATALOGUE=/data/ydx/igem/293T_CG_GRCh38_retry/293T_CG.GRCh38.PASS.biallelic.SNV.vcf.gz
OUT="$PROJECT/final_with_293T_catalogue"

python3 pipeline/scripts/catalogue/filter_existing_treatment_specific_by_293T.py \
  --treatment-specific "$INPUT" \
  --catalogue-vcf "$CATALOGUE" \
  --output-dir "$OUT"
```

For each RNA record and catalogue record, the script constructs a normalized exact-allele key:

```text
normalized chromosome
+ 1-based position
+ reference allele
+ alternate allele
```

An exact match receives `genomic_catalogue_overlap = 1`; otherwise it receives `0`.

## Learn

### Evidence compatibility

The older RNA table could be compared with the catalogue, but it could not be retroactively described as independently depth-qualified in all controls. The compatibility route therefore performs only the supported operation: exact catalogue exclusion.

### Auditability

The 16 overlapping alleles remain in a separate output. This makes each exclusion inspectable and prevents silent data loss.

### Catalogue boundary

The catalogue is external to the exact CU5.17 experimental batch. An exact overlap supports interpretation as a plausible genomic variant. Absence from the catalogue does not prove that the experimental cells lack a subline-specific variant.

### Final terminology

Recommended description:

> catalogue-filtered treatment-associated C-to-U screening candidates

The retained records should not be presented as definitive off-targets or as fully depth-qualified editing events without additional evidence.

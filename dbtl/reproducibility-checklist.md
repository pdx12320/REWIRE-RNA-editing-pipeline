# Reproducibility checklist

Use this checklist before repeating or extending the analysis.

## 1. Reference consistency

- [ ] The same GRCh38 FASTA is used by STAR, GATK, REDItools2-related coordinate processing, VEP interpretation, CrossMap output validation and bcftools normalization.
- [ ] The FASTA has a `.fai` index.
- [ ] Sequence-dictionary requirements for GATK are satisfied.
- [ ] Chromosome prefixes are handled consistently.
- [ ] Supplementary-contig version suffixes such as `.1` and `.2` are preserved.

Reference used in the frozen project:

```text
/data/ydx/igem/GRCh38.primary_assembly.genome.fa
```

## 2. RNA sample manifest

- [ ] The manifest contains exactly three treated and three control libraries.
- [ ] Sample names match BAM, REDItools2 and depth-table filenames.
- [ ] SRA accession and condition labels are frozen before analysis.

```text
pipeline/config/samples.tsv
```

## 3. FASTQ and alignment checks

- [ ] Paired FASTQ files exist and are non-empty.
- [ ] STAR output BAM files are readable.
- [ ] GATK input BAM headers contain read groups.
- [ ] MarkDuplicates metrics are retained.
- [ ] SplitNCigarReads output is coordinate-sorted and indexed.

Useful checks:

```bash
samtools quickcheck sample.bam
samtools view -H sample.bam | grep '^@RG'
samtools idxstats sample.bam | head
```

## 4. REDItools2 checks

- [ ] The Python 2 environment contains compatible dependencies.
- [ ] `mpirun`, `mpicc` and `mpi4py` use the same MPI implementation.
- [ ] The requested MPI workers do not exceed available slots.
- [ ] REDItools2 output exists for all six samples.
- [ ] Supplementary contigs are not truncated by filename parsing.
- [ ] Core thresholds are recorded.

Frozen settings:

```text
-S
-me 20
mapping quality >=20
base quality >=30
```

## 5. Candidate and VEP checks

- [ ] The union VCF and BED are generated from all six sample call tables.
- [ ] VEP output corresponds to the same GRCh38 assembly.
- [ ] Positive-strand C>T and negative-strand G>A interpretations are implemented.
- [ ] Ambiguous transcript orientation is not silently forced.

## 6. Candidate-depth checks for the strict route

- [ ] Six candidate-depth tables exist.
- [ ] Each table contains chromosome, 1-based position and depth.
- [ ] All expected union coordinates are represented or missingness is explained.
- [ ] `all_replicates_depth_pass` is generated by the current integration implementation.

```text
$PROJECT/candidate_depth/<sample>.candidate_depth.tsv.gz
```

If these files are unavailable, do not claim that control non-calls are independently depth-qualified.

## 7. Catalogue source checks

- [ ] The source is the HEK293 Genome Project `293T_CG` VCF.
- [ ] The source assembly is recorded as build36/hg18.
- [ ] The UCSC `hg18ToHg38` chain is available locally and passes `gzip -t`.
- [ ] Input compression is detected from content rather than extension.
- [ ] The source file checksum is recorded.

## 8. Catalogue conversion checks

- [ ] PASS biallelic SNP selection was applied.
- [ ] CrossMap unmapped records were counted.
- [ ] REF alleles were checked against the project GRCh38 FASTA.
- [ ] Incompatible records were removed.
- [ ] The output was normalized and coordinate-sorted.
- [ ] bgzip and tabix indexing succeeded.
- [ ] QC and checksums were written.

Frozen audit targets:

```text
source PASS biallelic SNPs       2,914,465
CrossMap-unmapped records            5,979
GRCh38 REF mismatches removed       22,761
final GRCh38 SNPs                2,885,725
C>T or G>A subset                  997,698
```

A materially different value should trigger investigation rather than automatic acceptance.

## 9. Exact-allele integration checks

- [ ] RNA and catalogue coordinates are both GRCh38.
- [ ] The key includes chromosome, position, REF and ALT.
- [ ] Chromosome-prefix normalization does not alter contig identity.
- [ ] Catalogue-overlapping records are retained in a separate table.
- [ ] Final counts satisfy subtraction arithmetic.

Frozen result:

```text
3,349 pre-catalogue candidates
- 16 exact overlaps
= 3,333 retained screening candidates
```

## 10. Evidence-language checks

- [ ] The 293T catalogue is described as external rather than matched WGS.
- [ ] Control non-calls are not converted to zero editing without BAM evidence.
- [ ] Retained sites are called screening candidates.
- [ ] Absence from the catalogue is not described as proof of an SNV-free site.
- [ ] Orthogonal validation is identified as a future requirement.

Recommended term:

> catalogue-filtered treatment-associated C-to-U screening candidates

## 11. Files to preserve

```text
pipeline/config/samples.tsv
pipeline/env/*.yml
pipeline/scripts/rna/*
pipeline/scripts/catalogue/*
pipeline/CATALOGUE_PROVENANCE.md
pipeline/OUTPUTS.md
pipeline/TROUBLESHOOTING.md
dbtl/*
results/final_summary.tsv
```

Large raw and intermediate files may remain outside GitHub, but their paths, checksums and generation commands should be recorded.
